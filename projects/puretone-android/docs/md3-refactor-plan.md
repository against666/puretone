## 一、背景与目标

PureTone 早期界面是"能用就行"的写法：颜色角色只定义了 13 个、正文字号被压到 13sp（低于 M3 规范 14sp）、圆角在业务代码里手写、间距 12/13/16/24 混用、没有动效语言。界面单薄、深色模式色偏、大屏上内容被拉满一整行。

**目标**：把界面收敛到 MD3 规范的一套令牌与组件上，同时不动功能、路由、数据层。

**范围**：`ui/` 包下的全部页面与共享组件。
**不在范围内**：播放器内核（Media3）、数据库、在线接口、下载逻辑、发版流程。

## 三、待办（按优先级）

### P0 · 宽屏真机验证与修正

**问题**：NavigationRail 分支只做了代码级验证，没有在真实宽屏上跑过。截图不可替代真机。

| 任务 | 验收标准 | 风险 |
|---|---|---|
| P0-1 在平板/折叠屏（或模拟器 800×1280 / 1024×768）上跑主流程 | 三个主页面布局正常、无内容被裁切、迷你条不遮挡列表 | 手上只有手机，需要模拟器时间成本 |
| P0-2 子页面（歌单详情、使用说明、加歌页）在宽屏下的表现 | 内容限宽生效、返回逻辑正常 | 这些页面自带返回按钮，未适配侧轨层级 |
| P0-3 横屏手机（约 800×360） | 不出现"矮屏 + 侧轨"挤压 | 横屏高度不足时侧轨可能占满高度 |

### P1 · 动效接入

**问题**：`Motion.kt` 定义了缓动与时长，但页面转场仍是 `EnterTransition.None`（早期为消除残影刻意关掉）。现在令牌齐了，可以按规范做成体系。

| 任务 | 具体做法 | 验收标准 |
|---|---|---|
| P1-1 列表 → 播放页 | `sharedAxis`（Z 轴）+ `emphasizedDecelerate` 进入、`emphasizedAccelerate` 退出，`MEDIUM_2 (300ms)` | 转场不出现残影（这是当初关掉动画的原因，需重点回归） |
| P1-2 底部标签切换 | `fadeIn/fadeOut` + `SHORT_4 (200ms)` | 切换跟手、无闪烁 |
| P1-3 列表项按下反馈 | 缩放 `PressedScale (0.98)` + `animateFloatAsState` | 点击有实体感，滚动时不误触 |

**风险**：P1-1 必须复现并验证「残影」问题是否真的解决；如果仍出现，退回 `None` 并记录原因。

### P2 · 形状令牌收口

**问题**：`AlbumArtBox` 的圆角由调用方传参（`corner = 8.dp`、`6.dp`），没有走 `shapes`。

| 任务 | 做法 |
|---|---|
| P2-1 给 `AlbumArtBox` 增加 `shape: Shape` 重载，保留旧 `corner` 参数兼容 | 逐处替换调用点，视觉回归 |
| P2-2 封面尺寸规范化 | 56dp（列表）/ 48dp（迷你条）/ 大图（播放页）三档，写进组件注释 |

### P3 · 视觉细节

| 任务 | 说明 |
|---|---|
| P3-1 分隔线内缩对齐 | 歌单页分隔线起点应与文字起点严格对齐（当前 88dp 是估算值） |
| P3-2 音源芯片溢出 | 五枚芯片在 360dp 屏幕上放不下，最后一枚被裁切；可改为两行 `FlowRow` 或缩小内边距 |
| P3-3 空状态配图 | 搜索空状态只有一行文字，可加一枚弱化的图标（`Icons.Outlined.SearchOff` 之类） |
| P3-4 播放页控制区视觉重量 | 主按钮 72dp 与两侧按钮的层级可再拉开（主按钮用 `primaryContainer` 填充） |

### P4 · 无障碍完整审计

当前只补了进度条与图标描述，还没有系统化对照 MD3 审计清单。

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 对比度 | 逐角色核对 `onX` 与 `X` 配对 | 正文 ≥4.5:1、大字/图形 ≥3:1 |
| 焦点顺序 | 外接键盘 Tab 遍历 | 顺序与视觉一致，无焦点陷阱 |
| 字号缩放 | 系统字号调到 200% | 无文字截断、按钮不重叠 |
| 触控目标 | 检查所有可点区域 | ≥48×48dp |
| 语义完整性 | TalkBack 逐页朗读 | 每个交互元素有可理解的描述，装饰性图片 `contentDescription = null` |
| 动态取色 | Android 12+ 开启动态取色后回归 | 不出现硬编码色残留 |

### P5 · 组件复用收口

当前多处重复实现同类列表行（音乐库行、歌单行、搜索结果行）。可抽出 `TrackListItem` / `SectionHeader` 两个共享组件，减少后续改动成本。

**注意**：这是重构，不是重写——只在视觉与行为完全一致时替换，避免引入回归。

## 五、风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| 转场动画引发残影（历史问题） | 播放页出现前后界面叠加 | 单条转场独立开关；异常立即退回 `None` 并记录 |
| 令牌替换改变布局尺寸 | 长标题截断、按钮换行 | 每次改动只动一类（先间距、再形状、最后字阶），逐批截图比对 |
| 宽屏分支只在模拟器验证 | 真实平板出现意外 | 优先找一台真机/折叠屏；模拟器结论标注"未真机验证" |
| 字号放大 200% 后溢出 | 可访问性不达标 | P4 中专项测试，必要时给关键文本加 `maxLines` + 省略 |

所有改动均在 Git 中逐批提交，任意批次可单独回滚（`git revert <commit>`）。

## 六、明确不做的事

- 不更换播放器内核、不改动数据层与网络层
- 不引入新的 UI 依赖（包括 `material3-window-size-class`、`materialkolor`）
- 不做深色/浅色之外的主题变体（如高对比度独立配色）
- 不重写页面结构（保持现有路由与导航层级）
